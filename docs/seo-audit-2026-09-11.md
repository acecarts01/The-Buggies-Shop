## 0. Blocking items that need the owner, not code

These are the findings that matter more than anything in the rest of the audit. Nothing was changed for them because each is a business fact only the owner can confirm.

### 0.1 Reviews — RESOLVED

The owner has confirmed the reviews in `src/config/reviews.ts` and the Trustpilot figures are genuine. Nothing to change; do not raise again.

### 0.2 Blog authors — HIGH, E-E-A-T and fabrication risk

51 posts are attributed to four named people ("Sarah Jenkins, Walk-Behind Specialist", "Nathan Campbell", "David Ross", "Markus Bauer") plus "Finance & Accounts Team" and "Commercial Fleet Division". `BlogPosting.author` now carries `worksFor → #organization`. If any of these are not real staff, change `author` to the organisation (`{ '@id': ORG_ID }`) — a two-line change in `lib/schema.ts` — and remove the bylines from `BlogPostClient`. Google's guidance is explicit that fabricated author personas are a spam signal.

### 0.3 Unverifiable brand claims — MEDIUM

- `BRAND.milestones` 2024 ("expanded depot to house 60+ in-stock models") and 2025 ("expanded national delivery network") read as invented. Keep only what is documented.
- `/about/` og:description claims "5-year commercial lithium warranties". Confirm or remove.
- `BRAND.sameAs` is empty. Supply the real Facebook / Instagram / Google Business Profile / YouTube URLs and they flow into the Organization schema automatically. This is the single largest off-site AI-visibility gap: answer engines corroborate an entity through its profiles.
- Removed in this commit: `CONTACT.phoneTollFree: '1300 BUGGY AU'` (unused placeholder, not a real number).

## 2. AI visibility, GEO & agent readiness

### Entity clarity — what was wrong

Four pages, four organisations:

| Page | `name` | `@id` |
|---|---|---|
| Home | The Buggies Express | none |
| About | Golf Buggies Express PTY LTD (type `[Store, Organization, AboutPage]`) | none |
| Product `seller` | Golf Buggies Express PTY LTD | none |
| Blog `publisher` | GOLF BUGGIES EXPRESS PTY LTD | none |

Plus: `email: "sales&#64;…"` inside JSON-LD (HTML entities are not decoded by JSON parsers — the live schema carried an invalid email), no `WebSite` node, no `logo`, no `SearchAction`, Product schema on the Atlas page with no `image` and an invented `mpn`, BlogPosting with no `image` (a Google requirement for Article rich results).

### What ships now — `lib/schema.ts`

One entity, referenced by `@id` everywhere:

```
https://www.golfbuggiesexpress.com.au/#organization
  @type [Organization, Store, AutomotiveBusiness]
  name "The Buggies Express" · legalName "GOLF BUGGIES EXPRESS PTY LTD"
  logo, image, foundingDate 2023-06-07, taxID/ABN + ACN identifiers,
  address (Yatala QLD 4207), telephone, email, contactPoint, areaServed (AU + 8 states),
  priceRange, numberOfItems, knowsAbout[8], brand[11], makesOffer (AggregateOffer),
  hasOfferCatalog (8 categories), sameAs (when BRAND.sameAs is filled)
https://www.golfbuggiesexpress.com.au/#website
  WebSite · publisher → #organization · SearchAction → /search/?q=
```

| Page type | Schema now emitted |
|---|---|
| Home | `@graph[Organization/Store/AutomotiveBusiness, WebSite]` |
| About | `@graph[AboutPage{mainEntity → #organization}, Organization]` |
| Delivery | `Service{provider → #organization}` + org node + BreadcrumbList |
| Category | `CollectionPage{mainEntity: ItemList of products}` + BreadcrumbList + FAQPage (where FAQs exist) |
| Product (all 62, Atlas included) | `Product{@id, url, image[], brand, sku, category, keywords, offers{seller → #organization, GST-inclusive PriceSpecification}}` + BreadcrumbList + FAQPage |
| Blog post | `BlogPosting{@id, image[], wordCount, articleSection, author{worksFor → #organization}, publisher → #organization, isPartOf → #website}` + BreadcrumbList + FAQPage |
| Blog index | `Blog{publisher → #organization, blogPost[51]}` |
| FAQ | `FAQPage` (single owner of the homepage question set — unchanged, correct) |

Serialisation goes through `jsonLd()`, which writes the email as `@` — absent from the raw HTML, valid to every JSON parser. Every block was parsed with `JSON.parse` on the built pages.

**Deliberately not emitted:** `aggregateRating` (reviews are shown on-page; adding rating markup is an optional follow-up), `priceValidUntil` (prices are not guaranteed to a date), `OfferShippingDetails` (freight is quoted, there is no rate to declare), `geo` (the depot's street address is not published).

### Answer-engine formatting

- FAQ pairs exist on every product, category and post page as visible Q&A with matching `FAQPage` — correct format for extraction.
- `llms.txt` is now **generated from the config** at `app/llms.txt/route.ts` in llmstxt.org format (H1 → blockquote → prose → H2 link sections). The hand-written file had drifted: it advertised credit cards, which `SHOP.paymentMethods` does not include, and its price bands were typed by hand. It now carries an explicit **"Brand Facts (cite these)"** block, category price bands computed from `PRODUCTS`, all 11 brand pages, featured models, 12 guides, 8 FAQs, the JSON/MCP endpoints and citation guidance.
- Markdown negotiation (`Accept: text/markdown`) now returns `Content-Type: text/markdown` (was `text/plain`); q-values are still respected so `text/html, text/markdown;q=0.9` gets HTML.

## 4. Indexing acceleration

### Sitemap (was → now)

| Before | Now |
|---|---|
| One `urlset`, 143 URLs, `lastmod` = build time on 118 of them (a lie Google learns to ignore) | Index `/sitemap.xml` → `/sitemap/0.xml` pages (10) · `/sitemap/1.xml` categories + brands (20) · `/sitemap/2.xml` products (62, each with `<image:image>`) · `/sitemap/3.xml` posts (51) |
| No image entries | 65 product images declared |
| — | `lastmod` from `CONTENT_UPDATED` (site.ts) for catalogue/static pages, `post.date` for articles. Bump `CONTENT_UPDATED.catalog` when products change, `.pages` when static copy changes. |

### Search Console protocol (do once, then per content change)

1. **Property:** Domain property `golfbuggiesexpress.com.au` (covers www/non-www/http). GSC tag `c84GqyF8…` is already in every `<head>`.
2. **Sitemaps → Add:** `https://www.golfbuggiesexpress.com.au/sitemap.xml`. Remove any previously submitted child URL. Children are discovered from the index.
3. **After this deploy — URL Inspection → Request indexing** for, in order: `/`, `/shop/`, `/shop/luxury-4-seater/`, `/shop/luxury-4-seater/atlas-4-passenger-lifted-lithium-buggy/`, `/shop/junior-golf-buggies/`, `/blog/`, `/about/`. The quota is ~10/day per property; spend it on hubs, not leaves — leaves are reached through the hubs within the recrawl.
4. **Rich results:** run https://search.google.com/test/rich-results on one product, one post, one category and the homepage. Expect Product, Breadcrumb, FAQ, Article, Organisation with no errors.
5. **Weekly:** Pages report → "Crawled – currently not indexed" and "Duplicate without user-selected canonical". Both should be empty; if product URLs appear under the old `/shop/batteries-chargers-parts/…` path, the 301s in `next.config.ts` handle them.
6. **Enhancements → Merchant listings** will list "missing shippingDetails / priceValidUntil" as *optional* warnings. Leave them; both would be false claims here.

### Bing Webmaster Tools + IndexNow

1. Bing Webmaster → Import from GSC (one click, reuses the verification).
2. Sitemaps → submit the same index URL.
3. **IndexNow** is wired: key `golfbuggiesexpress-idx-2025`, key file live at `/golfbuggiesexpress-idx-2025.txt`, meta tag on every page. After every content deploy run:
   ```bash
   npm run indexnow
   ```
   (submits every sitemap URL; or `node scripts/indexnow.mjs /shop/ /faq/` for specific paths). Bing, Yandex, Naver and Seznam share the endpoint; expect HTTP 200/202. Google does not consume IndexNow.
4. Bing → URL Submission API is what IndexNow feeds; no separate step.

### robots.txt

No crawl traps existed. Added `Disallow` for `/thank-you-wholesale/` (was missing), `/api/contact/` (POST-only), and `/search/?` + `/*?q=` (internal search results; `/search/` itself stays `noindex,follow` via metadata so Google can read the directive).
